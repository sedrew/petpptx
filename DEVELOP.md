1. **Type** — Specifies the kind of change:
   - `feat` — New feature or functionality.
   - `fix` — Bug fix.
   - `docs` — Documentation updates.
   - `refactor` — Code refactoring (no functional changes).
   - `style` — Formatting or styling (no logic changes).
   - `test` — Adding or updating tests.
   - `chore` — Miscellaneous (e.g., dependency updates, config changes).

2. **Short Description** — A concise summary of the change (up to 50 characters if possible), written in the imperative mood (e.g., "add", "fix").

3. **Optional Context** — In parentheses, you can specify what the change relates to (e.g., module, file, or task name).
